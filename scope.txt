1. Executive Summary & Project Purpose
This Project Scope document establishes the updated functional, architectural, and methodological requirements for the
DCS 404 final project: Machine Learning & Transformer-Based Spam Message Detection. Following formal review and
professor feedback (update.md), the project has transitioned from an initial single-model baseline to a comprehensive,
production-ready Natural Language Processing (NLP) benchmark that addresses real-world machine learning
challenges: class imbalance, data leakage prevention, lexical pattern discovery, deep transformer sequence modeling,
and interactive deployment.
The primary objective is to build, evaluate, and deploy an end-to-end system that classifies user-submitted text
messages as either legitimate communications (Ham) or unsolicited fraudulent messages (Spam). The system
synthesizes the complete DCS 404 curriculum: exploratory data analysis, text feature engineering (TF-IDF), class
imbalance remediation using Synthetic Minority Over-sampling Technique (SMOTE), traditional statistical learning
(Logistic Regression and Multinomial Naive Bayes), fine-tuned state-of-the-art transformer architectures (DistilBERT
and DistilRoBERTa), and an interactive 7-section Streamlit dashboard with real-time inference scoring.
Key Milestone Enhancements
Professor Feedback Updates (update.md):
• Handle Class Imbalance with SMOTE: Apply SMOTE strictly to training features; maintain zero leakage on test data.
• Traditional Classifiers: Use Logistic Regression as the main SMOTE model; analyze why SMOTE impacts Naive Bayes.
• Deep Transformer Models: Fine-tune DistilBERT and DistilRoBERTa in Google Colab for sequence classification.
• Exploratory Analytics: Generate high-resolution Spam and Ham Word Clouds and message length distributions.
• Multi-Dimensional Benchmark: Evaluate Accuracy, Precision, Recall, F1, Latency, and Architectural Trade-Offs.
• Streamlit UI Enhancement: Expand interface into 7 structured sections with an interactive live testing playground.

2. Project Objectives
• Data Preparation & Hygiene: Clean the raw UCI SMS Spam Collection (5,572 records), verify zero null entries, and
prune 403 exact duplicates to yield 5,169 distinct messages (4,516 Ham [87.4%], 653 Spam [12.6%]).
• Rigorous Anti-Leakage Protocol: Perform stratified 80/20 partitioning (4,135 train / 1,034 test) prior to vectorization.
Fit TfidfVectorizer strictly on training text to eliminate target leakage into the test set.
• Class Imbalance Remediation via SMOTE: Apply SMOTE exclusively to the training TF-IDF matrix, synthetically
balancing 3,613 Ham and 522 Spam samples to an equal 3,613:3,613 distribution, while preserving the test set in its
authentic natural state.

4. Dataset Specifications & Data Hygiene
The project utilizes the canonical UCI SMS Spam Collection repository (Almeida & Hidalgo). The dataset represents
authentic mobile text messages collected from Singapore National University corpora, UK spam SMS complaints, and
the Grumbletext website.
• Total Raw Records: 5,572 rows (4,825 raw ham, 747 raw spam).
• Deduplication: 403 exact duplicate messages were removed to eliminate artificial frequency bias and memorization.
• Cleaned Dataset Size: 5,169 unique samples (4,516 Ham [87.37%], 653 Spam [12.63%]).
• Train/Test Partition: Stratified 80/20 split -> Training: 4,135 samples (3,613 Ham, 522 Spam); Test: 1,034 samples
(903 Ham, 131 Spam).
• SMOTE Balanced Training Partition: 7,226 samples (3,613 Ham, 3,613 Spam), achieved strictly in TF-IDF feature
space.

Operational Evaluation: Trade-Off Analysis Insights:
• Latency Disparity: Traditional ML executes inference in 0.0008 ms/sample (~1.25M messages/sec). Transformers
require 70-71 ms/sample (~14 messages/sec on CPU) — a 90,000x latency advantage for traditional ML.
• Compute & Training: Traditional models train in under 0.05 seconds. Transformers require ~45 minutes of CPU
execution or 3 minutes on GPU.
• Decision Rule: Deploy Naive Bayes or Logistic Regression for real-time telecom switches; deploy DistilBERT for highvalue enterprise email auditing.

8. Streamlit User Interface Specification
The web application is structured into 7 dedicated sections accessible via a navigation sidebar:
• Section 1. Home: Executive introduction, project scope, and end-to-end architecture pipeline diagrams.
• Section 2. Dataset Overview: Summary cards (5,169 records, 87.4% Ham, 12.6% Spam), raw data samples, and
deduplication audit metrics.
• Section 3. Data Exploration: Interactive class distribution plots, SMOTE balancing diagrams, and character/word
length histograms.
• Section 4. Spam & Ham Word Clouds: Side-by-side high-resolution word clouds displaying key fraud triggers versus
conversational ham lexicons.
• Section 5. Model Performance: Detailed breakdown for each model: Confusion Matrices, Classification Reports, and
ROC curves.
• Section 6. Model Comparison: Multi-metric comparative bar charts (Accuracy, Precision, Recall, F1) and operational
latency benchmark tables.
• Section 7. Live Spam Prediction: Interactive playground: users paste custom messages, select any of the 4 models,
click 'Analyze Message', and view real-time SPAM/HAM prediction cards with confidence meters.
